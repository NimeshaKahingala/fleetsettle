## Findings

### QA-2026-08-16-01 — Any `ActionSheet`/`Sheet` selection that closes itself and navigates in the same handler silently reverts the navigation, on any real touch device

Severity: high — this is core navigation, not a cosmetic gap, on the
device class this product is built for (M-1).

Reproduction 1 — the originally-reported flow:

1. Sign in to QA at 390×844 with touch/coarse-pointer emulation.
2. Home → `Add` → `New trip`.
3. Tap a vehicle (`NC-1234`).

Observed: the picker closed, then the app landed back on `/` (Home). The
route never reached `/vehicles/:id/trip/new`. Repeated once more with a
second vehicle (`QA-52656`) — identical result.

Reproduction 2 — no nested picker, a single ordinary `ActionSheet`:

1. Vehicles → `QA-52656` → `Vehicle actions` → `Book trip`.

Observed: landed back on `/vehicles/:id` (the vehicle overview screen it
started from), never reaching `/vehicles/:id/trip/new`.

Reproduction 3 — same sheet, a different destination, to rule out
anything trip-specific:

1. Vehicles → `QA-52656` → `Vehicle actions` → `View calendar`.

Observed: landed back on `/vehicles/:id`, never reaching
`/vehicles/:id/calendar`.

Three for three. No console/page error in any case.

**Evidence — `window.history` instrumented directly**, wrapping
`pushState`/`back` and listening for `popstate`, rather than inferred from
source. Reproduction 2's raw log:

```
{"op":"pushState","len":9,"url":".../vehicles/<id>"}                 // Vehicle actions opens
{"op":"pushState","len":10,"url":".../vehicles/<id>"}                // (see note below)
{"op":"back","len":11,"url":".../vehicles/<id>/trip/new"}            // <-- fires AFTER the router already navigated
{"op":"popstate","len":11,"url":".../vehicles/<id>"}                 // lands back on the vehicle screen
```

The same shape held in all three reproductions: the router's own
`pushState` for the new route is already applied — `location.href` reads
the destination URL — by the time `SheetHistoryStack`'s deferred
`history.back()` fires. That `back()` was only ever meant to remove the
closing sheet's own pushed entry, but the *current* entry at that instant
is the router's freshly-pushed one, so `back()` consumes that instead.
`popstate` ~15–20ms later completes the revert.

**Mechanism.** [`SheetHistoryStack`](web/src/lib/useMobileHistoryDismiss.ts#L38)'s
own class doc ([:8-36](web/src/lib/useMobileHistoryDismiss.ts#L8-L36))
states plainly that it assumes it is the *only* thing that touches
`window.history`, and defers its `pushState`/`back()` reconciliation to a
microtask specifically so that same-commit sheet handoffs net to zero
before touching the browser. Nothing in it accounts for a third actor —
TanStack Router's own history adapter — pushing an entry in the same
event-handler tick. Both call sites involved are otherwise unremarkable:
[`ReasonPicker`](web/src/components/ReasonPicker.tsx#L48-L51)'s `onClick`
runs `onOpenChange(false); onSelect(reason);`, and `router.tsx`'s
[`onBookTrip`](web/src/app/router.tsx#L720-L727) runs
`setQuickAddOpen(false); navigate(...)`. The race lives entirely in the
shared primitive, not in either caller — confirmed by reproductions 2/3,
which have no nested picker and no `QuickAddSheet` involvement at all,
just one ordinary `ActionSheet` closing and one ordinary `navigate()`.

**Not the failure LT-13 was filed to describe.** LT-13 opened 14 Aug
naming "New trip → choose a vehicle renders no vehicle choices" — that
exact symptom is GAP-125 (an unrelated `?? []`-during-fetch bug), closed
15 Aug and confirmed still fixed in the Passes above. What "continue the
wider sweep" turned up instead is a second, unrelated, more severe defect
one step later in the same flow: not a blank list, a silently reverted
navigation, and not scoped to Quick Add at all.

**Existing regression coverage does not catch this.**
[`e2e/mobile-sheet-history.touch.spec.ts`](web/e2e/mobile-sheet-history.touch.spec.ts) —
the touch-emulation regression file GAP-104 itself produced — only
exercises a sheet closing and **opening another sheet** (Quick Add → Fuel,
Quick Add → Expense). It has no case for a sheet closing and **navigating
to a route**, which is the exact shape that fails here. That gap in
coverage is why this shipped and stayed invisible through every prior
`npm run check` run.

Filed as **GAP-134** (TRACKER.md).

## Test Limitations

- Verified under Chrome DevTools MCP / CDP mobile+touch emulation, not yet
  on physical iOS Safari or Android Chrome — LT-10 remains the open item
  for that, and nothing here is iOS/Android-specific (the mechanism is
  pure JS History API logic), so CDP emulation should be a faithful test
  of it, but real-device confirmation is still worth doing before or
  alongside a fix.
- Only three call sites were exercised end-to-end. The mechanism is
  general to any `ActionSheet`/`Sheet` action that navigates rather than
  opening another sheet — the full inventory of affected call sites is
  unconfirmed and is part of GAP-134's own remaining scope.
